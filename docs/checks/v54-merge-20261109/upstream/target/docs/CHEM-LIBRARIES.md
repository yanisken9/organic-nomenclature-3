# Chemistry / Cheminformatics Library Landscape (reference)

Context for this project: a no-build static JS app teaching organic nomenclature in Greek/English. Keeps **JSmol** (3D; expert in-house knowledge, not revisited) and **JSME** (2D/SMILES I/O; confirmed to already support SMILES→2D generation and SMARTS query input). This doc surveys alternatives and complements considered, for future reference — not a decision to switch anything today.

## Currently used — keep as-is

| Library | Role here | Notes |
|---|---|---|
| **JSmol** ([jmol.sourceforge.net](https://jmol.sourceforge.net/), [wiki](https://wiki.jmol.org/index.php/Main_Page)) | 3D rendering, scripting, camera/scenario capture | Mature, deeply integrated (atom/bond selection scripting, `moveto` camera replay for scenarios). No reason to touch. |
| **JSME** ([jsme-editor.github.io](https://jsme-editor.github.io/)) | 2D depiction + full-edit input, SMILES/MOL I/O | Confirmed: generates 2D coords from SMILES, canonical SMILES export, substructure-query→SMARTS translation, reaction SMILES/SMIRKS. Satisfies this project's functional needs even if the drawing UI isn't loved. |

## 2D structure editors (JSME alternatives, if UI is ever revisited)

| Library | Features | Pros | Cons |
|---|---|---|---|
| **Kekule.js** ([site](http://partridgejiang.github.io/Kekule.js/), [GitHub](https://github.com/partridgejiang/Kekule.js)) | MIT-licensed JS toolkit; `Kekule.Editor.Composer` 2D editor, 3D model building, SMILES/MOL/InChI I/O, own structure utilities | Modern editor UX (templates, stereo bonds, better undo/redo than JSME per community reports); pure JS, no backend | Smaller community/docs than JSME; would need its own integration layer for extraction (atoms/bonds/coords) |
| **Ketcher** (EPAM) ([site](https://lifescience.opensource.epam.com/ketcher/), [GitHub](https://github.com/epam/ketcher)) | Apache-2.0 web editor; reactions, macromolecules (HELM), R-groups/S-groups, OCR-from-image import, ACS drawing-standard styling, React component | Actively maintained, polished modern UI, "standalone" WASM mode (via bundled Indigo) needs no server, good docs, used in production (Streamlit components etc.) | Standalone WASM bundle is sizable; full feature set (macromolecules, HELM) is overkill for this app's scope; built around Indigo toolkit as its chemistry backend (see below) |
| **ChemDoodle Web Components** ([web.chemdoodle.com](https://web.chemdoodle.com/), [IUPAC demo](https://web.chemdoodle.com/demos/iupac-naming)) | Pure-JS 2D/3D graphics + cheminformatics, publication-quality rendering, reaction/spectra support, built-in IUPAC naming demo | Polished visuals, unified 2D+3D API, commercial naming feature available | **Commercial license required** beyond non-commercial/eval use — real cost for an educational deployment |
| **OpenChemLib / openchemlib-js** ([openchemlib-js](https://github.com/cheminfo/openchemlib-js), [Java original](https://github.com/actelion/openchemlib)) | JS port (GWT-compiled) of the Java OpenChemLib toolkit (the engine behind DataWarrior); molecule/reaction editing, ring perception, stereochemistry, canonicalization, substructure search, 2D editing | BSD/MIT-licensed, free, actively maintained (Zakodium), used in production (Datagrok), decent docs, **also doubles as a cheminformatics toolkit** (ring perception etc.), not just an editor | Editor UI less polished/less known than Ketcher/Kekule; smaller ecosystem than RDKit for heavy cheminformatics |
| **SmilesDrawer** ([GitHub](https://github.com/reymond-group/smilesDrawer), [live site](https://reymond-group.github.io/smilesDrawer)) | Tiny, dependency-free JS; parses + depicts SMILES to SVG/canvas, handles complex/bridged rings well, very fast | Extremely lightweight, zero deps, great for *display-only* use (e.g. rendering a SMILES as a static picture) | **Not an editor** — no drawing/input UI at all, one-way (SMILES→picture) only |

## 3D viewers (reference only — JSmol is staying)

| Library | Features | Pros | Cons |
|---|---|---|---|
| **3Dmol.js** ([3dmol.org](https://3dmol.org/), [GitHub](https://github.com/3dmol/3Dmol.js)) | WebGL molecular graphics; PDB/SDF/MOL2/XYZ/CIF/MMTF formats, surfaces, cartoons, labels, shapes, clickable interactivity | Modern WebGL performance, clean API, BSD license, actively maintained | Would require rebuilding the entire JSmol scripting/`moveto`-replay integration — not worth it given expertise/investment already in JSmol |
| **Mol\*** ([molstar.org](https://molstar.org/)) | Successor to NGL (which RCSB/PDB officially deprecated in 2024 — [notice](https://www.rcsb.org/news/6661c72262451e4e35915f7a)); large-structure 3D viewer, modern web app architecture | Now the de facto standard for protein/PDB-scale visualization, actively developed | Overkill and heavier than needed for small-molecule teaching use; **NGL itself is deprecated, don't consider it** |

## Cheminformatics / structure-analysis toolkits (detection layer, not editors)

| Library | Features | Pros | Cons |
|---|---|---|---|
| **RDKit.js** (`@rdkit/rdkit`) ([rdkitjs.com](https://www.rdkitjs.com/), [GitHub](https://github.com/rdkit/rdkit-js)) | Official WASM build of RDKit's "MinimalLib" C++ subset: ring perception (SSSR), aromaticity, canonical ranking, SMARTS/substructure matching. **No IUPAC naming.** | Industry-standard algorithms, free, in-browser, zero backend, well documented at rdkitjs.com | ~7 MB WASM (raw); no high-level UI components (build your own) |
| **OpenChemLib** (see above) | Same toolkit as the editor row — ring perception, aromaticity, canonicalization, substructure search | Free, smaller footprint than RDKit.js, already doubles as editor if ever needed | Less exhaustive cheminformatics surface than RDKit (fewer descriptors, no ML/fingerprint-fit ecosystem) |
| **Indigo toolkit** (EPAM) ([site](https://lifescience.opensource.epam.com/indigo/), [GitHub](https://github.com/epam/Indigo)) | C++ cheminformatics engine (layout, properties, import/export); backs Ketcher | Mature, used in production (Bingo, Ketcher) | **GPL license (copyleft)** — a real consideration for a project that may want permissive licensing; mainly consumed via Ketcher/WASM wrapper, not standalone in plain JS |
| **chematic** (`@kent-tokyo/chematic`) ([GitHub](https://github.com/kent-tokyo/chematic), [npm](https://www.npmjs.com/package/@kent-tokyo/chematic)) | New (2026) pure-Rust→WASM cheminformatics toolkit: SMILES/SMARTS, SSSR ring perception, 190+ descriptors, fingerprints, MCS, reactions; explicitly benchmarked against RDKit for parity | Notably smaller WASM bundle and faster cold-init than RDKit.js per its own published benchmarks; no C++ toolchain needed; includes an experimental `chematic-iupac` crate | **Very new, single/small-team project**, not independently vetted here, benchmarks are self-published; nowhere near RDKit's track record or community size — watch, don't depend on yet |

## Nomenclature (name generation / parsing)

| Tool | Direction | Features | Pros | Cons |
|---|---|---|---|---|
| **PubChem PUG-REST + CIR** *(already this project's architecture)* ([PUG-REST docs](https://pubchemdocs.ncbi.nlm.nih.gov/pug-rest), [CIR resolver](https://cactus.nci.nih.gov/chemical/structure)) | structure→name (lookup) | Authoritative `IUPACName` field, free, no install | Correct for any indexed compound, zero engine-building cost | Only works for compounds already in the database — the "15 novel molecules" gap is exactly this limitation; requires network |
| **OPSIN** ([GitHub](https://github.com/dan2097/opsin), [EBI service](https://www.ebi.ac.uk/opsin)) | **name→structure** (reverse) | Mature, free, Java (MIT), used by ChemDoodle's own "Name to Structure" feature, excellent heterocycle/fused-ring coverage per independent review (~80%+ in spot checks) | The most proven free nomenclature tool that exists; perfect for **round-trip validation** of names this engine generates | Not structure→name — doesn't answer "what do I call this," only "does this name parse back correctly" |
| **ACD/Name** (ACD/Labs) ([product page](https://www.acdlabs.com/products/name/)) | structure→name | Generates names in 19+ languages **including Greek**, handles organic/biochem/organometallic | The commercial gold standard; genuinely multilingual including the target language | Paid, proprietary, not embeddable in a free web app |
| **ChemAxon Structure-to-Name** (Marvin) ([user guide](https://docs.chemaxon.com/lts-krypton/structure-to-name-user-guide/)) | structure→name | IUPAC 2013 recommendations, traditional names, CAS numbers | Strong accuracy, desktop/API tooling | Commercial license required |
| **ChemDoodle "Structure to Name"** | structure→name | Own proprietary algorithm; its reverse direction is literally "Powered by OPSIN" | Nice demo, decent free tier | Commercial beyond the free tier; still a black box for a teaching tool that needs to *explain* rules, not just output an answer |
| **NISPO** *(new, 2026)* ([GitHub](https://github.com/oxpig/nispo), [arXiv:2607.26113](https://arxiv.org/abs/2607.26113)) | structure→name | Open-source, RDKit-based; validated by round-tripping output through OPSIN; 98.1% round-trip accuracy on a large PubChem benchmark | First credible **open-source** attempt at the forward direction | Python, not JS; weeks/months old; "round-trip accuracy" ≠ "preferred-IUPAC-name correctness" (multiple name variants can round-trip); not proven at OPSIN's maturity level |
| **OpenClatura** ([GitHub](https://github.com/lamalab-org/openclatura), [PyPI](https://pypi.org/project/openclatura/), [ChemRxiv preprint](https://doi.org/10.26434/chemrxiv.15006114/v2), [agent API](https://openclatura.org/llms.txt)) | structure→name | Open-source MIT, deterministic rule-based (Blue Book 2013) with **inspectable decision traces** bound to atoms/bonds, OPSIN round-trip auditing per answer, plain-text/JSON web API (`/name?smiles=`), QM9 100% / PubChem 99.76% / ZINC22 97.70% | Computed from structure — speaks where record-lookup oracles go silent (novel molecules); traces fit this project's explain-the-name philosophy | Beta; school-vs-PIN conventions differ by design (retained substituents, implied locants) so it disagrees with this engine exactly where PubChem does — second opinion only, never auto-truth |
| **chematic-iupac** | structure→name | Experimental crate inside the `chematic` WASM toolkit | Would run directly in-browser if it matures | Extremely early, unverified, part of an already-new project |

## Recommendation for this project

1. **Keep JSME + JSmol.** Both satisfy the functional requirements (SMILES↔2D, SMARTS query input, 3D scripting); migration cost isn't justified by a UI preference alone.
2. **If the JSME drawing UX is revisited later**, Kekule.js and Ketcher are the two real contenders — Ketcher is more actively maintained and polished but pulls in Indigo (GPL) and a larger bundle; Kekule.js is lighter-weight and MIT-licensed. Either would only replace the *input* editor, not touch JSmol or the naming engine.
3. **For cyclic-nomenclature support** (stated scope: simple rings with substituents), add a ring-perception layer — **RDKit.js** (proven, heavier) or **OpenChemLib** (lighter, dual-purpose as editor+toolkit, worth a look since it's less resource-hungry) — purely as the "sensing" layer, same role `functionalGroupObj` plays today. The actual naming *rules* still need to be hand-written rule tables, same pattern as the acyclic engine.
4. **For naming generation itself**, stay with PubChem/CIR oracle + the project's own rule engine. Don't adopt NISPO/OpenClatura/chematic-iupac yet — too new, not JS-native, and "round-trip correct" isn't the same bar as "pedagogically correct." Worth revisiting in 6–12 months if they mature. Of the three, OpenClatura deserves the closest watch: its decision traces (which atoms/bonds produced which name fragment) are the closest any tool comes to this project's explain-the-name philosophy — but it's Python, beta, and unevaluated here.
    - **2026-11-06 update (v54 Phase 1): OpenClatura integrated as a second oracle (display only).** `fFetchIUPAC_OC` (`iupac-54.js`, `/name?smiles=` + `format=json`, single attempt, fail-soft) feeds an "IUPAC (OpenClatura)" row with OPSIN status in the molecule info panel (select-time fetch, cached on entry) and in the draft preview (post-PubChem, canonical-first SMILES), and persists as `openclaturaEN`/`openclaturaOpsin` on accepted customs (saved files carry it). Verbatim display only — no verdicts, no auto-correction (Phase 2: shared-comparator second verdict, P3 queue).
5. **OPSIN** is the one addition worth considering soon, purely as a **validation tool** (offline, scriptable, Java): round-trip this engine's own generated names through it to catch naming bugs, independent of PubChem's lookup-only coverage.
