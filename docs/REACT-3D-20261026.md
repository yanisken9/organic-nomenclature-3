# Namelecule React — visible 3D pilot, 2026-10-26

The approved extension exposes the existing 3D renderer for the same three
molecules in the local React preview. The primary conversation implements it;
an independent Reviewer checks the frozen final content. No new chemistry,
lesson, dependency, commit, push or publication is part of this stage.

## Scope and behavior

Base HEAD `168e3cec01f941a84d40bbe0dc07156e7baa35d0`, branch `react-library-pilot`.
The earlier molecule selector and name-analysis panel were already present,
uncommitted and separately reviewed. This stage extends their adapter/host,
`MoleculePreview.jsx`, `main.jsx`, CSS, README and focused documentation/checks.
The original v51 application, all core/viewer/data/teaching files, all MOL/SDFs
and all twelve lesson JSONs remain unchanged. Stable `thesis-work` remains at
`3673c390c1fb1b7cbcc79411a6e1e3720e97f7ab`.

React offers 2D/3D buttons, a shared molecule selector, zoom and name components.
3D uses native JSmol rotation and the existing `fZoom3D`. The 2D form controls are
disabled in 3D. Returning preserves the 2D form/zoom and current analysis;
changing molecule preserves the form/view and resets zoom/analysis as before.
The same iframe remains mounted across molecule/view changes. A ResizeObserver
uses public `Jmol.resizeApplet` to match the visible host dimensions.

The v4 protocol retains source/origin/session/request-ID validation. The host
checks the actual loaded SDF URL, atom serials/elements and canonical bond
edges/orders against the existing parser's 3D arrays. An ordered JSmol variable
marker confirms queued loading/style commands have completed. React requires
matching model metadata before showing the frame; components are unavailable
while a model change is pending. Commands run serially to prevent native zoom's
`quit` from cancelling later commands/markers. Stale responses remain rejected.
Initial load/command deadlines, error feedback, fallback, retry and cleanup remain.

The generated host sets existing `Info.script` to `set defaultDirectory` at the
repository root. JSmol had resolved relative `load` and `script` paths below
`react-preview/dist/`, despite the HTML base. This configuration fixes the host's
asset resolution without editing the original page, loader or molecular files.
See the public [Info API](https://wiki.jmol.org/index.php/Jmol_JavaScript_Object/Info)
and [JSmol functions](https://wiki.jmol.org/index.php/Jmol_JavaScript_Object/Functions).
This remains a complete legacy runtime in a same-origin frame, not a security
sandbox or a native React molecular renderer.

## Diagnostic history and limits

A cached old `dist/index.html` initially loaded the previous v3 bundle alongside
a v4 host. Fresh query URLs resolved this harness issue; it was not a proven
JSmol boxed-number bug. The initial 3D comparison used different 2D forms and
found a differing internal selection property; matching the forms removed it.
Actual overlapping native zoom commands exposed a readiness failure. A focused
probe reproduced it; serial adapter execution fixed it, followed by the complete
relevant rerun. The regression harness was also adjusted to await actual command
ACKs instead of assuming synchronous execution during rapid component toggles.
These failed attempts are not reported as successful checks.

Only these three molecules are exposed in the React viewer. No new full-library
126-molecule/283-step runtime certification, Safari, real mobile touch gestures,
offline, Drupal embedding, screen-reader, PNG export or unavailable-network test
was performed. Legacy JSME/JSmol/CDN dependencies remain required, including for
verified startup of the 2D view. This stage does not migrate the lesson player or
replace the welcome-page compatibility bridge.

Open locally: `http://127.0.0.1:8013/react-preview/dist/?v=3d-20261026#/viewer`.
This requires the local server and is not a shareable professor/publication URL.

## 2026-10-27 — independent review correction

The first independent review identified P2: selecting a new molecule in 3D,
requesting 2D, then immediately using zoom could expose an enabled button before
the host's model/view transition completed. The host rejected that request and
the parent awaited an ACK that would never arrive. Both zoom buttons now remain
disabled for every pending model/view transition, regardless of requested view.
Only their two React disabled conditions changed; bridge, chemistry, cameras,
renderer, name logic and molecular assets are unchanged by this correction.

The final build passed (21modules; JS269.53kB/81.29gzip, CSS4.84kB/1.34gzip).
The actual Firefox transition test now includes this exact delayed-model case,
verifies disabled premature zoom, successful completion and subsequent usable
zoom. Its ordered-zoom sequence, actual 9.23s model failure, retry and pending
unmount also pass with zero JS errors. Evidence:
`docs/checks/react-3d-transitions-20261027.json`. The 26October full 33+9 2D/name
and 3model/11component browser suites remain earlier Developer evidence for the
unchanged bridge/renderer; they are not represented as a full rerun of this new
bundle. Independent re-review outcome and any limits are recorded in the journals.
The original 26October manifest is historical after this correction; use the new
`react-3d-reviewed-target-20261027.json` for the final target.
